# TOKUDER TCH の誤り訂正（解読結果）

実装: `tokuder_neurodec/fec.py`（numpy のみ）。テスト: `tests/test_fec.py`。

## 仕様

ARIB STD-T99 Annex 2 第5章が定めているのは「72 bit / 20 ms = 音声 48 bit + 誤り訂正 24 bit」までで、内部の配置は公開されていません。
受信したフレームだけを解析して、次の構造であることを特定しました。

| 受信 bit 位置（0 始まり、送信順） | 内容 |
|---|---|
| 3i（i = 0..23） | Golay 語 A の第 i bit（拡大 Golay [24,12,8]） |
| 3i + 1 | Golay 語 B の第 i bit（A と同じ符号） |
| 3i + 2 | 無保護の音声 bit |

- 音声 48 bit の内訳: Golay A の情報 12 bit、Golay B の情報 12 bit、無保護 24 bit。
- 線形符号で、スクランブル（定数 XOR）はありません。全 0 も符号語です。
- 受信 bit 順でのパリティ検査行列は `fec.H`（12×24、RREF）。A と B で同じです。
- 訂正能力:
  - 硬判定では、Golay 1 語あたり 3 bit まで訂正できます（4 bit は検出のみ）。
  - 軟判定では、4096 符号語に対する最尤復号を行います（`soft_decode`）。
- 符号語の中でどの 12 bit が「真の」情報 bit なのかは分かっていません。
  - `info48` は固定の情報集合 `INFO` を使います。そのため、得られる 48 bit は真の音声 bit を固定の線形変換で並べ替えたものです。
  - 同梱のデコーダーはこの 48 bit で学習しているので、問題になりません。

## 根拠

1. **線形符号であること**: |LLR| ≥ 20 のフレーム 67,047 個が張る GF(2) 部分空間は 48 次元で、0 を含みます。つまり線形 [72,48] 符号です。
2. **検査式が実データで成り立つこと**: 零空間から得た 24 本の検査式を、全 282,376 フレームの 99.97 % が満たしました。
   - 満たさないフレームは、送信の先頭（同期を捕捉した直後）に集中しています。
   - 誤りは LLR の小さい bit にあり、実際の通信路誤りと考えられます。
3. **重み分布が拡大 Golay 符号 2 個分と一致すること**: 双対符号の 2^24 語を全数列挙し、MacWilliams 恒等式で符号の重み分布を求めました。
   - 重み k < 8 の符号語の数は B_k = C(24,k) でした。ここから、検査されない bit が 24 個あると分かります。
   - 重み 8 の符号語は C(24,8) より 1518 = 2 × 759 個多くありました。これは拡大 Golay 符号 2 個分の重み分布と一致します。
4. **位置の規則**: 検査式に一度も現れない列は 2, 5, 8, …, 71 でした。重み 8 の検査式の台は、すべて位置 ≡ 0 (mod 3) か、すべて位置 ≡ 1 (mod 3) のどちらかに収まります。
5. **独立な検証**: 規格書の試験データ（Table Annex 2-7-1、1031 Hz トーン。解析には使っていません）のシンドロームは、A・B とも 0 でした。
